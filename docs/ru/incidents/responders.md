# Responders и participants

В 2.5 запросы помощи и операционные назначения принадлежат Incident.
Основной assignee Incident и список participants — разные сущности.

## Запрос помощи

```http
POST /api/incidents/17/responders
Content-Type: application/json

{"target_type":"user","target_user_id":42,"message":"Проверь базу данных","expires_after_minutes":30}
```

Другие типы адресата: `team`, `rotation`, `escalation_policy`. Передавайте ровно
один соответствующий `target_*_id`. Длина `message` — до 2000 символов;
`expires_after_minutes`, если задан, — от 1 до 10080. Ответ `201` содержит запрос
с адресатом, статусом, участниками действий и временем. Повторный POST создаёт
отдельный запрос: ключа идемпотентности у этого endpoint нет.

Список запросов: `GET /api/incidents/17/responders`. Ответ на запрос:

```http
PUT /api/incidents/17/responders/8
Content-Type: application/json

{"status":"accepted","response_message":"Начинаю проверку"}
```

Из `requested` доступны `accepted`, `declined`, `expired`; принятый запрос можно
перевести в `resolved`. Сервер проверяет принадлежность адресату и доступ к
Incident. Принятие запроса команды/ротации/политики назначает конкретного человека.
Одновременные accept/expire/назначения сериализованы. Повтор того же разрешённого
перехода идемпотентен; другой пользователь не может забрать уже принятый запрос.
Истечение срока или конфликт назначения возвращает `409`, недопустимый переход —
`400`. `response_message` ограничен 2000 символами.

[Центр уведомлений](notification-center.md) показывает доступные пользователю
ожидающие запросы. `201` подтверждает сохранение запроса, а не доставку адресату:
email и push имеют независимые [повторные попытки](stakeholders.md#доставка-и-повторы).

## Прямое назначение

```http
POST /api/incidents/17/participants
Content-Type: application/json

{"user_id":42,"role":"commander"}
```

Роли: `commander`, `responder`, `communications`. Пользователь должен быть активен
и состоять в группе Incident. Допускаются один активный commander и одно активное
назначение на пару пользователь/роль. У пользователя могут быть разные роли.
Создание возвращает `201`; дубль или конфликт — `409`.
Прямое назначение не отправляет приглашение responder.

`GET /api/incidents/17/participants` возвращает принятые назначения.
`DELETE /api/incidents/17/participants/<participant_id>` завершает назначение,
сохраняя историю (`204`). Повторное удаление возвращает `404`.

Для чтения нужны права чтения команды Incident; для записи — права реагирования
и аутентифицированный пользователь. Назначение, события и аудит сохраняются одной
транзакцией. Назначение не выдаёт пользователю новые права команды и не меняет ACK.

Старые маршруты responders на AlertGroup в текущем коде отсутствуют. Перед
обновлением интеграций проверьте [решение о совместимости](release-notes-2.5.md#решение-о-совместимости).
