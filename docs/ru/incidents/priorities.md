# Приоритеты инцидентов

IncidentRelay использует шкалу приоритетов P1-P5 для групп алертов / инцидентов.

| Приоритет | Значение |
|---|---|
| `p1` | P1 Критический |
| `p2` | P2 Высокий |
| `p3` | P3 Средний |
| `p4` | P4 Низкий |
| `p5` | P5 Информационный |

Приоритет отделён от серьёзности (severity) алерта. Серьёзность описывает входящий сигнал. Приоритет описывает важность реагирования на инцидент.

## Автоматический приоритет

Когда входящий алерт создаёт или обновляет инцидент, IncidentRelay может определить приоритет по серьёзности алерта.

Автоматические изменения приоритета следуют консервативным правилам:

- новый инцидент получает приоритет, производный от серьёзности входящего алерта;
- автоматический приоритет может быть повышен при поступлении более важного сигнала;
- автоматический приоритет не понижается более поздним менее важным сигналом;
- вручную выбранный приоритет не перезаписывается серьёзностью входящего алерта.

Это сохраняет полезность автоматической маршрутизации, не теряя намерения ответственного.

## Ручной приоритет

Ответственные могут вручную задать приоритет инцидента из интерфейса деталей инцидента.

Ручные изменения приоритета:

- помечают приоритет как выбранный вручную;
- обновляют редактируемые сообщения уведомлений там, где это поддерживается;
- добавляют контекст в таймлайн;
- могут уведомлять заинтересованные стороны, запросившие уведомления об изменении приоритета.

Ручное переопределение приоритета можно удалить из представления деталей инцидента, выбрав **Reset to automatic**.

После сброса IncidentRelay восстанавливает приоритет в соответствии с действующим режимом обновления политики:

- `initial_only` восстанавливает приоритет, выбранный для первого алерта;
- `raise_only` восстанавливает наивысший приоритет, найденный в истории алертов инцидента;
- `recalculate` выбирает наивысший приоритет среди текущих активных алертов.

Если ни один подходящий приоритет алерта недоступен, используется запасной вариант политики или сопоставление серьёзности.

## Фильтрация и сортировка

Страница Alerts поддерживает фильтрацию по приоритету и сортировку с приоритетом в первую очередь. Приоритет также отображается в деталях алерта и сводках дашборда.

Используйте фильтры по приоритету, когда большой список инцидентов требует сортировки по важности реагирования, а не по чистой серьёзности.

## Уведомления

Приоритет включается в вывод уведомлений для поддерживаемых каналов:

- email;
- Mattermost;
- Telegram;
- браузерные push-уведомления.

Заголовки уведомлений могут включать короткую метку приоритета, например:

```text
[P1] Database unavailable
```
