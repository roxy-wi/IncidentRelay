# Выпускная проверка — 27 октября 2026

**Выпуск блокирует PostgreSQL-регрессия resolve/reopen ниже.** Документация и
OpenAPI обновлены. Удаление responder/stakeholder API и хранилища AlertGroup
согласовано как breaking change 2.5.

Проверен `7738f25` с незакоммиченными изменениями workspace и документации в ветке
`release/2.5.0`. Коммитов и пуша не было. Использовались отдельные копии приложения
и одноразовые БД; база рабочего checkout не затрагивалась.

Перепроверка PostgreSQL включала UTF-8, доступный временный каталог и исправленный
тест activity: теперь он проверяет готовую спецификацию, а не формат исходника.
Эти ошибки устранены. Два оставшихся первоначальных сбоя требуют POSIX/Linux:
container bootstrap и проверка file mode 0600. Единственный оставшийся
функциональный сбой — гонка ниже. Исходный PostgreSQL-прогон не является зелёным.

## Воспроизводимый блокер

`tests/postgresql/test_alert_reopen_concurrency.py::test_manual_resolve_during_uncommitted_reopen_is_noop`
завершается `TimeoutError` на `resolving.result(timeout=15)`. Сбой воспроизведён
в отдельном PostgreSQL-наборе и в общем прогоне; остальные девять специальных
PostgreSQL-тестов прошли. Сценарий ожидает, что ручной resolve, увидевший старое
resolved-состояние, завершится без изменения, пока новый occurrence ещё не
зафиксирован. Текущий resolve ожидает блокировку строки AlertGroup.

Повторять только на одноразовой PostgreSQL БД с тестовой конфигурацией:

```sh
pytest tests/postgresql/test_alert_reopen_concurrency.py::test_manual_resolve_during_uncommitted_reopen_is_noop -vv
```

До релиза нужно исправить или уточнить контракт конкурентного resolve/reopen
и добиться прохождения теста. Поведение lifecycle в рамках пункта документации
не менялось.

## Миграция и ограничения среды

Исходники 2.4 проверены по release commit
`21ea27d92927242ed499b7584a276f47cb1c68cd` с учётом переводов строк Git.
В каждой legacy-таблице из пяти записей на обеих БД получены одна сохранённая,
одна объединённая, две unmapped и одна ambiguous. Проверены технические
комментарии, флаги уведомлений, история объединения, новые вставки/sequence,
повторный no-op migrate и соответствие схем моделям.

Из 78 пропусков общего набора 47 Helm и один браузерный тест затем прошли отдельно;
одна PostgreSQL-only проверка выполнена на PostgreSQL. Остались 29 Linux container
проверок. Десять POSIX multiprocess metrics тестов не собирались; два deselected
теста также требуют POSIX/Linux. Заглушка только импорта `fcntl` позволила загрузить
приложение на Windows, но не подтверждает работу POSIX locking. Эти проверки
нуждаются в Linux CI.

Временный PostgreSQL слушал только loopback. Для ускорения отключались ожидание
синхронизации WAL и fsync: проверялись SQL-транзакции и гонки, а не сохранность
после сбоя ОС или питания. После проверок сервер остановлен. Матрица Python
3.10–3.14 на Linux и настоящий запуск контейнеров локально не выполнялись.
Обновлённый CI включает PostgreSQL-specific тесты и Chromium workspace на Python
3.12; для текущих незакоммиченных файлов удалённый CI не запускался.
