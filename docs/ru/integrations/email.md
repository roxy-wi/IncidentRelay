# Канал Email

Email — это исходящий канал уведомлений. Он отправляет уведомления об алертах на email-адрес из профиля назначенного пользователя.

Каналы Email не хранят получателей и не хранят настройки транспорта SMTP.

## Модель доставки

```text
Alert assignee -> assignee.email -> global SMTP server
```

Необходимые данные:

| Расположение | Необходимое значение |
|---|---|
| Профиль пользователя | `email` |
| Глобальная конфигурация | настройки `[smtp]` |
| Конфигурация канала Email | опциональный `html_template`, опциональный `notify_on_severities` |

Если у назначенного пользователя нет email-адреса, доставка по email завершается ошибкой с понятным сообщением.

## Глобальная конфигурация SMTP

Настройте SMTP в файле глобальной конфигурации:

```ini
[smtp]
host = 127.0.0.1
port = 25
from = incidentrelay@example.com
use_tls = false
user =
password =
```

Для SMTP-сервера с аутентификацией:

```ini
[smtp]
host = smtp.example.com
port = 587
from = incidentrelay@example.com
use_tls = true
user = incidentrelay@example.com
password = change-me
```

Если SMTP-сервер не поддерживает AUTH, оставьте `user` и `password` пустыми.

## Конфигурация канала

Минимальная конфигурация канала Email:

```json
{}
```

С пользовательским HTML-шаблоном:

```json
{
  "html_template": "<h1>{event_type}: {title}</h1><p>{message}</p>"
}
```

С фильтром важности:

```json
{
  "notify_on_severities": ["critical", "high"],
  "html_template": "<h1>{event_type}: {title}</h1><p>{message}</p>"
}
```

## Кнопка теста

При тестировании канала Email IncidentRelay отправляет тестовое письмо на email-адрес из профиля текущего пользователя.

Если у текущего пользователя нет email-адреса, тест возвращает ошибку с указанием пользователю задать email в своём профиле.

## Устранение неполадок

### Тест работает, но реальные алерты не приходят

Проверьте назначенного пользователя реального алерта:

- у алерта есть назначенный пользователь;
- у назначенного пользователя есть email-адрес;
- канал привязан к сопоставленному маршруту;
- фильтр важности канала разрешает уровень важности алерта;
- SMTP-релей принял и доставил сообщение.

### Лог сообщает `notification sent`, но почтовый ящик пуст

SMTP-сервер принял сообщение от IncidentRelay. Проверьте логи нижестоящего SMTP-релея, карантин спама, политику получателя, SPF/DMARC и правила почтового ящика.
