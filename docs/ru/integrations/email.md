# Канал Email

Email — это исходящий канал уведомлений. SMTP по-прежнему настраивается глобально, а **способ выбора получателя** задаётся в канале. Маршруты, политики уведомлений и эскалации не изменяются.

## Режимы получателя

В настройках Email channel доступны три варианта:

| Режим | Получатель обычного уведомления |
|---|---|
| `assignee` (по умолчанию) | Email назначенного пользователя из профиля |
| `fallback` | Email назначенного пользователя, а если его нет — `recipient_email` |
| `fixed` | Всегда указанный `recipient_email`, независимо от assignee |

Для `fallback` и `fixed` необходимо указать **один корректный email-адрес** (`recipient_email`). Список адресов через запятую и имя получателя не поддерживаются. Ранее созданные каналы продолжают работать через `assignee.email`, без изменения настроек и миграций.

Режим `fallback` помогает при отсутствии назначенного пользователя или email в его профиле, например в Simple Rotation. **Он не отслеживает ошибки Slack, Telegram или других каналов.** Для постоянных уведомлений в общий резервный ящик выберите `fixed` и добавьте канал в тот же маршрут или Notification Policy.

## Глобальная конфигурация SMTP

```ini
[smtp]
host = 127.0.0.1
port = 25
from = incidentrelay@example.com
use_tls = false
user =
password =
```

При использовании SMTP с аутентификацией задайте логин, пароль и TLS по требованиям сервера. Параметры SMTP не хранятся в Email channel.

## Примеры конфигурации

Без изменений, как в предыдущих версиях:

```json
{}
```

Резервный адрес при отсутствии email у assignee:

```json
{
  "recipient_mode": "fallback",
  "recipient_email": "oncall-backup@example.com"
}
```

Постоянная отправка на общий адрес:

```json
{
  "recipient_mode": "fixed",
  "recipient_email": "ops@example.com",
  "notify_on_severities": ["critical", "high"]
}
```

HTML-шаблон можно дополнительно настроить через `html_template`.

## Кнопка Test

При тестировании письмо **всегда отправляется на email текущего пользователя**, даже в режимах `fixed` и `fallback`. Так тест SMTP не отправляет неожиданное письмо в общий ящик. Тест не подтверждает доступность настроенного фиксированного адреса — её нужно проверять обычной доставкой алерта.

Если у пользователя нет email в профиле, Test возвращает ошибку.

## Устранение неполадок

При отсутствии реальных писем проверьте режим получателя, адрес, назначенного пользователя, маршрут и фильтр серьёзности, а также логи SMTP. Источник выбранного адреса записывается как `recipient_source` без раскрытия самого адреса.
