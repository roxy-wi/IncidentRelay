# Чек-лист быстрого старта

Используйте этот чек-лист после установки.

## Установка

- [ ] Установлено по руководству для Docker, RPM или ручной установки с systemd
- [ ] Файл конфигурации существует
- [ ] `INCIDENTRELAY_CONFIG_FILE` указывает на файл конфигурации
- [ ] Веб-сервис запущен
- [ ] Сервис планировщика запущен
- [ ] Миграции применены командой `python manage.py migrate`
- [ ] Первый глобальный пользователь-администратор существует

## Базовая настройка

- [ ] `public_base_url` установлен в реальный внешний URL
- [ ] Настройки базы данных корректны
- [ ] SMTP настроен глобально, если будет использоваться канал email
- [ ] Голосовой провайдер настроен, если будут использоваться голосовые вызовы
- [ ] Ключи VAPID для браузерных push-уведомлений настроены, если будут использоваться PWA/браузерные push
- [ ] Логи видны в журнале, логах контейнера или файле лога

## RBAC и команды

- [ ] Группа существует
- [ ] Пользователи существуют
- [ ] Пользователи добавлены в группу
- [ ] Роли группы назначены: `viewer`, `editor`, `user_admin`
- [ ] Команда существует
- [ ] Пользователи команды добавлены из той же группы
- [ ] Роли команды назначены: `viewer`, `responder`, `manager`

## Настройка дежурства

- [ ] Ротация существует
- [ ] Участники ротации в правильном порядке
- [ ] Интервал напоминаний настроен:

```text
0 reminders disabled
>= 60 reminders enabled
```

- [ ] Политика эскалации настроена для команды
- [ ] Представление календаря показывает ожидаемых дежурных пользователей

## Настройка уведомлений

- [ ] Существует хотя бы один канал уведомлений
- [ ] Канал включён
- [ ] Фильтр серьёзности канала корректен или пуст
- [ ] Необходимые контактные поля профиля пользователя заполнены
- [ ] Тест канала работает
- [ ] Ответственные, которым нужны браузерные push-уведомления, включили их в разделе Profile
- [ ] Тест браузерных push-уведомлений из раздела Profile работает

Браузерные push-уведомления действуют на уровне профиля и не требуют привязки к каналу или маршруту.

## Настройка маршрута

- [ ] Маршрут существует
- [ ] Источник маршрута соответствует типу входящей интеграции
- [ ] Маршрут привязан к одному или нескольким каналам
- [ ] Матчер маршрута сопоставляется с входящим payload
- [ ] Токен приёма маршрута скопирован в систему мониторинга

## Проверка

- [ ] Отправьте тестовый алерт в состоянии firing
- [ ] Алерт появляется на странице Alerts
- [ ] Уведомление доставлено
- [ ] ACK работает для ответственного/менеджера
- [ ] Resolve работает
- [ ] Заглушки подавляют совпадающие новые алерты
