# Начало работы

Выберите метод установки, соответствующий вашему окружению.

## Методы установки

| Метод | Когда использовать | Руководство |
|---|---|---|
| Docker Compose | Вам нужен самый быстрый старт или развёртывание на основе контейнеров | [Установка через Docker](docker.md) |
| RPM-пакет | Вы используете RHEL, Rocky Linux, AlmaLinux или CentOS Stream | [Установка через RPM](rpm-installation.md) |
| Ручная установка с systemd | Вы хотите запускать из исходного кода или самостоятельно управлять окружением Python | [Ручная установка с systemd](systemd.md) |

Все методы используют одну и ту же модель приложения:

```text
web service        -> HTTP API, UI, incoming integrations
scheduler service  -> reminders, escalations, periodic jobs
```

## Общие дальнейшие шаги

После установки:

1. Ознакомьтесь с разделом [Настройка](configuration.md).
2. Запустите миграции базы данных, если ваш метод установки не выполнил их автоматически.
3. Создайте первого глобального пользователя-администратора.
4. Откройте веб-интерфейс и следуйте разделу [Первый вход и настройка](first-login.md).
5. Настройте хотя бы один маршрут и один канал уведомлений.
6. Отправьте тестовый алерт.

После того как первый алерт заработает, продолжайте с:

- [Управление инцидентами](../incidents/index.md)
- [Сервисы](../services/index.md)
- [Планирование](../scheduling/index.md)
- [Интеграции](../integrations/index.md)

## Важные имена путей и переменных окружения

Файл конфигурации выбирается через:

```text
INCIDENTRELAY_CONFIG_FILE
```

Используйте точное имя, указанное выше. Старое имя `ONCALL_CONFIG_FILE` использовать не следует.

Рекомендуемые пути для неконтейнерных инсталляций:

```text
/etc/incidentrelay/incidentrelay.conf
/var/lib/incidentrelay
/var/log/incidentrelay
/usr/local/lib/incidentrelay/voice_providers
```
