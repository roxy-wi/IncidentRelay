# Политики эскалации

Политики эскалации определяют многошаговую цепочку эскалации для алертов, направленных в команду.

Политика принадлежит одной команде и содержит упорядоченные правила. Каждое правило определяет:

- порядок эскалации;
- задержку перед переходом к следующему правилу;
- тип цели;
- целевой объект.

Поддерживаемые типы целей:

| Тип цели | Смысл |
|---|---|
| `rotation` | Назначить алерт текущему дежурному (on-call) пользователю из выбранной ротации |
| `user` | Назначить алерт конкретному пользователю команды |

Пример:

```text
Policy: Critical escalation

Rule 1:
  Target: Primary rotation
  Delay: 300 seconds

Rule 2:
  Target: Backup rotation
  Delay: 600 seconds

Rule 3:
  Target: Team lead user
  Delay: 900 seconds
```

## Режимы эскалации маршрута

Маршрут может работать в одном из двух режимов.

### Простой режим ротации

Маршрут указывает напрямую на ротацию.

```text
Route -> Rotation -> Team reminder-based escalation
```

В этом режиме IncidentRelay использует настройки команды:

- `Simple rotation escalation`;
- `Simple escalation after reminders`.

Напоминания продолжаются, пока алерт активен (firing), при условии, что у назначенной ротации включены напоминания.

### Режим политики эскалации

Маршрут указывает на политику эскалации.

```text
Route -> Escalation policy -> Rules
```

В этом режиме IncidentRelay использует правила политики и задержки правил.

Эскалация команды на основе напоминаний игнорируется для этого маршрута:

```text
Team escalation_enabled         ignored
Team escalation_after_reminders ignored
```

Напоминания всё ещё могут отправляться между шагами политики текущей цели эскалации. После того как политика завершила все правила и все разрешённые повторы, напоминания для этого алерта прекращаются. Алерт остаётся `firing`, пока не будет подтверждён (acknowledged) или разрешён.

## Количество повторов

`repeat_count` управляет тем, сколько дополнительных полных циклов политики разрешено после первого прохода по всем правилам.

| Значение | Смысл |
|---:|---|
| `0` | Выполнить все правила один раз, затем остановить напоминания политики |
| `1` | Выполнить все правила один раз, затем повторить полную цепочку правил ещё один раз |
| `2` | Выполнить все правила один раз, затем повторить полную цепочку правил ещё два раза |

Пример с двумя правилами и `repeat_count = 1`:

```text
Rule 1 -> Rule 2 -> Rule 1 -> Rule 2 -> stop
```

## Поведение напоминаний

Эскалация политики и напоминания связаны, но раздельны.

| Режим маршрута | Что управляет напоминаниями | Что управляет эскалацией |
|---|---|---|
| Простая ротация | Интервал напоминаний ротации | Team `Simple escalation after reminders` |
| Политика эскалации | Интервал напоминаний ротации текущей цели | Задержка правила политики |

Если маршрут использует политику эскалации:

- напоминания продолжаются, пока у политики ещё есть следующее правило или цикл повтора;
- напоминания прекращаются после того, как политика исчерпана;
- эскалация команды на основе напоминаний не выполняется.

Если маршрут не использует политику:

- используется старое поведение ротации на основе напоминаний;
- напоминания могут продолжаться бесконечно, пока алерт не будет подтверждён (acknowledged), разрешён, заглушён или назначен через ротацию с интервалом напоминаний `0`.

## Состояние алерта

Алерты, созданные из маршрута с политикой, хранят текущее состояние политики:

| Поле | Смысл |
|---|---|
| `escalation_policy_id` | Политика, используемая маршрутом |
| `escalation_rule_id` | Текущее правило |
| `escalation_level` | Количество уже выполненных эскалаций политики |
| `escalation_repeat_count` | Завершённые циклы повтора политики |
| `next_escalation_at` | Когда должен выполниться следующий шаг политики |
| `last_escalated_at` | Временная метка последней эскалации политики |

Это состояние отображается в деталях алерта, чтобы пользователи могли видеть, какому правилу политики в данный момент принадлежит алерт.

## Разрешения

Политики эскалации используют разрешения команды.

| Роль | Доступ |
|---|---|
| Team viewer | Просмотр политик и правил |
| Team responder | Просмотр политик и правил |
| Team manager | Создание, обновление и удаление политик и правил |
| Group editor | Может управлять политиками для команд, которые он может редактировать |
| Global admin | Полный доступ |

## Рекомендуемый порядок настройки

```text
1. Create a team
2. Create rotations and add members
3. Create notification channels
4. Create an escalation policy
5. Add policy rules
6. Create or edit a route
7. Set Escalation mode = Escalation policy
8. Select the policy
9. Attach route channels
10. Send a test alert
```

## Пример

```text
Team: Cloud OPS

Policy: Critical escalation
Repeat count: 1

Rule 1:
  Target type: rotation
  Target: Primary rotation
  Delay: 300

Rule 2:
  Target type: rotation
  Target: Backup rotation
  Delay: 600

Rule 3:
  Target type: user
  Target: cloud-lead
  Delay: 900
```

Хронология:

```text
12:00 alert created -> Primary rotation user notified
12:05 no ACK -> Backup rotation user notified
12:15 no ACK -> cloud-lead notified
12:30 repeat cycle starts, if repeat_count allows it
```
