# Профиль и персональные API-токены

Откройте:

```text
Profile
```

Страница профиля содержит идентификационные данные пользователя, контактные поля, контекст активной группы и персональные API-токены.

## Цвет пользователя

Каждому аккаунту назначается постоянный автоматический цвет по его ID. В **Профиль → Цвет пользователя** можно выбрать другой цвет и сохранить его. Он используется в аватарах, комментариях, участниках и стейкхолдерах инцидента, а также для заливки дежурств. Для читаемости текст становится чёрным или белым. При ручном выборе цвета могут совпадать.

API профиля принимает `color` в формате `#RRGGBB` и возвращает строчные hex-символы. Значение `null` восстанавливает автоматический цвет. Старые аккаунты получают цвет без перезаписи истории.

## Контактные поля

Заполните контактные поля, используемые каналами уведомлений.

| Поле | Используется |
|---|---|
| Email | Каналом Email |
| Phone | Каналом голосовых вызовов |
| Mattermost user ID | Для атрибуции действий в Mattermost |
| Telegram user ID | Для действий в Telegram |
| Slack user ID | Для атрибуции действий ACK/Resolve/Shelve в Slack; также используется при административной синхронизации Slack usergroup |

Каналы Email и голосовых вызовов отправляют на контактные данные из профиля назначенного пользователя, а не на списки получателей на уровне канала.

## Браузерные push-уведомления

Браузерные push-уведомления настраиваются для каждого пользователя в профиле.

Используйте:

```text
Enable push on this device
Send test push
Disable
```

Браузерные push-уведомления не являются каналом уведомлений. Когда алерт назначается пользователю, IncidentRelay может отправлять push-уведомления на активные устройства (браузер/PWA) пользователя. Кнопки ACK, Resolve, Shelve и Unshelve используют короткоживущие одноразовые токены действий.

Подробнее: [Браузерные push-уведомления](browser-push.md).

## Активная группа

Активная группа управляет текущим контекстом группы в интерфейсе и для операций в рамках группы.

Обычный пользователь видит группы, где у него есть активное членство. Глобальный администратор может получить доступ ко всем активным группам в соответствии с поведением глобального администратора.

## Персональные API-токены

Персональные токены обеспечивают доступ к API от имени текущего пользователя.

Рекомендуемые практики:

- используйте короткоживущие токены, где это возможно;
- ограничивайте использование токена нужной группой, когда интерфейс/API это поддерживает;
- ротируйте токены после компрометации;
- удаляйте неиспользуемые токены.

### Области доступа токенов

Токен может содержать любое сочетание детализированных областей доступа. Используйте области `:read` для отчётов и интеграций только для чтения, а соответствующую область `:write` добавляйте, только если интеграция должна изменять этот ресурс.

| Ресурс | Чтение | Запись |
|---|---|---|
| Алерты | `alerts:read` | `alerts:write` |
| Инциденты | `incidents:read` | `incidents:write` |
| Сервисы, включая бизнес-сервисы | `services:read` | `services:write` |
| Команды | `teams:read` | `teams:write` |
| Группы | `groups:read` | `groups:write` |
| Пользователи | `users:read` | `users:write` |
| Ротации и состояние дежурств | `rotations:read` | `rotations:write` |
| Календарь | `calendar:read` | `calendar:write` |
| Маршруты | `routes:read` | `routes:write` |
| Каналы | `channels:read` | `channels:write` |
| Окна обслуживания и заглушки | `maintenance:read` | `maintenance:write` |
| Heartbeats | `heartbeats:read` | `heartbeats:write` |
| Политики эскалации, уведомлений, приоритетов и matchers | `policies:read` | `policies:write` |
| Оркестрации событий | `orchestrations:read` | `orchestrations:write` |
| Журнал аудита | `audit:read` | — |
| Администрирование SSO | `sso:read` | `sso:write` |
| Администрирование Change-интеграций | `change-integrations:read` | `change-integrations:write` |
| Системные настройки | `system-settings:read` | `system-settings:write` |
| Текущий профиль и личные настройки уведомлений | `profile:read` | `profile:write` |

`/api/admin/change-integrations` принимает персональный API-токен глобального
администратора или администратора группы-владельца интеграции. Токен с ограничением
по группе управляет только её интеграциями. Центральные интеграции и корневые
маршруты управления заданиями требуют токен глобального администратора без
ограничений по группе и команде. Токены с ограничением по команде не допускаются.

`/api/admin/system-settings` требует токен глобального администратора без
ограничений по группе и команде. Для обоих API нужны отдельные scopes из таблицы
или `*`; `resources:*` и `changes:*` доступа не дают. Токен передаётся в заголовке
`Authorization: Bearer <api-token>`. JWT продолжает работать для веб-интерфейса.
Машинные токены `changes:ingest` используются только для приёма событий.

Для управления конфигурацией интеграций и системными настройками через Terraform
создайте персональный токен глобального администратора без ограничений по группе
и команде со следующими scopes:

```text
change-integrations:read
change-integrations:write
system-settings:read
system-settings:write
```

Для чтения текущего состояния и применения изменений нужны обе области: чтение
и запись. При изменении конфигурации интеграции передавайте `auth_revision` из
ответа GET как `expected_revision`. Ответ `409` означает, что конфигурация
изменилась параллельно: прочитайте текущее состояние и согласуйте с ним
намеченное изменение перед повторной попыткой.

Например, токен для отчётности только для чтения, объединяющей алерты с метаданными сервисов, инцидентов и команд, может использовать:

```text
alerts:read
services:read
incidents:read
teams:read
```

`resources:read` и `resources:write` — устаревшие агрегированные области доступа. Они продолжают поддерживаться для существующих клиентов и включают соответствующие детализированные области ресурсов, но в новых интеграциях следует предпочитать детализированные области.

`*` предоставляет все настроенные области доступа и доступен только глобальным администраторам. Области записи не включают области чтения автоматически; если клиенту нужны обе операции, выберите обе области.

Проверка областей доступа API-токенов закрывает доступ по умолчанию. Защищённый эндпоинт `/api/...` должен быть сопоставлен области доступа, прежде чем API-токен сможет к нему обратиться. Это не позволяет новым API-эндпоинтам незаметно становиться доступными существующим токенам.
